4.1. Temperature, Logits & Softmax

Day 3, Section 3.1 described the model evaluating a probability distribution over its vocabulary. Concretely, the model's raw, unnormalized scores for each candidate token are called logits. A function called Softmax converts these logits into probabilities that sum to 1.0. Temperature is the control that lets you reshape that probability distribution before a token is sampled from it — it decides how "adventurous" the model's word choice is.


# Program 4.0-1: Temperature Sampling & Softmax Distribution
import numpy as np

def sample_next_token(logits: dict, temperature: float = 1.0) -> str:
    """
    Simulates how an LLM applies Temperature scaling to raw logits (scores)
    before calculating probabilities with Softmax.
    """
    words = list(logits.keys())
    raw_scores = np.array(list(logits.values()), dtype=float)

    # Scale logits by temperature (preventing divide-by-zero)
    scaled_scores = raw_scores / max(temperature, 1e-5)

    # Apply Softmax to convert scores to probabilities that sum to 1.0
    exp_scores = np.exp(scaled_scores - np.max(scaled_scores))
    probabilities = exp_scores / np.sum(exp_scores)

    # Sample from the resulting probability distribution
    chosen_word = np.random.choice(words, p=probabilities)
    return chosen_word, dict(zip(words, probabilities.round(4)))

# Example model output scores for the next word after: "The sky is..."
raw_logits = {"blue": 8.0, "clear": 6.5, "dark": 5.0, "green": 0.5}

print("--- Temperature 0.1 (Deterministic / Low Entropy) ---")
word, probs = sample_next_token(raw_logits, temperature=0.1)
print(f"Probabilities: {probs}")
print(f"Selected: '{word}'\n")

print("--- Temperature 1.2 (Creative / High Entropy) ---")
word, probs = sample_next_token(raw_logits, temperature=1.2)
print(f"Probabilities: {probs}")
print(f"Selected: '{word}'")
Program 4.0-1: Temperature and Softmax Probability Sampling

Beyond temperature, a few other hyperparameters shape how tokens are chosen during generation:

Hyperparameter Typical Range Mechanism Best Used For
Temperature 0.0 – 1.5 Divides raw logits before Softmax. Lower values flatten rare tokens to zero. 0.0 for JSON extraction & SQL generation; 0.7 for open-ended conversation.
Top-P (Nucleus) 0.1 – 1.0 Cuts off sampling to the smallest pool of tokens whose cumulative probability exceeds P. Alternative to temperature; controls vocabulary diversity without flattening peaks.
Max Tokens 1 – 16,384 Hard ceiling on generated output tokens. Halts generation regardless of stop tokens. Preventing runaway reasoning loops and managing API token costs.
Stop Sequences List of strings Tells the generation loop to stop emitting tokens as soon as a marker appears. Ending a response cleanly, e.g. stopping before the model starts writing a new speaker turn.

Figure 4.0-4: The High-Level LLM Training Lifecycle

1. Training Data

The model is trained on very large collections of text (and, for some models, other data such as images or code), gathered from a wide variety of sources. The exact composition of any particular commercial model's training set is usually not fully public, so we won't make specific claims about it here — what matters for a beginner is the general idea: more varied, higher-quality text tends to produce a more capable model.

2. Tokenization

Just like at inference time, raw text is converted into tokens and then token IDs (Day 3, Section 3.2) before it can be processed by the neural network. Training and inference share the exact same tokenizer.

3. Training Objective: Next-Token Prediction

For every position in the training text, the model is given everything before it and asked to predict what comes next:

Input:  "The sky is"
Target: "blue"
"The sky is" → Model → Probability distribution
blue   0.72
clear  0.15
dark   0.08
green  0.01

Early in training, the model's weights are essentially random, so its guesses are close to noise. Training gradually reshapes the weights so more and more probability mass shifts toward the correct next token, across billions of examples.

4. Loss

The loss function measures how far the model's predicted probability distribution was from the actual target token — a low loss means the model assigned high probability to the correct token; a high loss means it didn't. We won't derive the exact math here; the key idea is simply "a single number that says how wrong the prediction was."

5. Backpropagation

Recall from Day 1 that a neural network is built from layers of connected weights. Backpropagation determines how much each of those weights contributed to the error (the loss), working backward from the output layer to the input layer, so their values can be adjusted in the direction that reduces the error.

6. Optimization

An optimizer (a piece of training software, not the model itself) uses the gradients computed by backpropagation to actually update the model's parameters — nudging each weight a small step in the direction that should reduce the loss next time.

7. Repetition

This entire cycle — predict, compare, calculate loss, backpropagate, update — is repeated over an enormous number of training examples, often many times over the same dataset. Individually each step is a small nudge; repeated billions or trillions of times, this is how the model learns the statistical patterns of language.

4.4. Hallucination & Limitations of LLMs

An LLM generates text based on learned patterns and probabilities — it does not have a built-in guarantee that every generated statement is factually correct. Understanding why, and what other limits apply, is essential before you start building agents on top of these models.

Hallucination

Example:
User: Who invented the fictional technology XYZ in 1842?
LLM: It may generate a confident-sounding, detailed answer — even though XYZ never existed.

A hallucination occurs when a model generates information that is unsupported, incorrect, or fabricated, while presenting it in a fluent and plausible way.

Why can this happen? It is not caused simply by "high temperature" — temperature can influence how much variation appears in the output, but it is not the fundamental cause. The real factors include:

  • The model is optimized to generate likely-sounding continuations, not to verify facts.
  • It has no built-in, guaranteed fact-checking mechanism.
  • Its training data can contain errors, gaps, or contradictions.
  • It may simply lack current or complete information about a topic.
  • Ambiguous prompts can lead to uncertain or inconsistent outputs.
  • Sampling (Section 4.1) introduces some randomness, which can surface less-likely, less-accurate continuations.

Other Important Limitations

  • Knowledge limitations: The model's learned knowledge comes from its training, and does not automatically update itself as new events happen in the world.
  • Context limitations: The model can only process a finite amount of text at once — its context window (Day 3, Section 3.4). Anything beyond that window is simply not visible to the model during that request.
  • Exact computation limitations: LLMs can struggle with exact arithmetic, counting characters, counting tokens, and other highly precise symbolic operations, because they are pattern predictors rather than calculators. External tools such as calculators or code execution can help with tasks like these.
  • Reliability limitations: The model can produce incorrect facts, incorrect code, malformed structured output, or inconsistent answers to the same question asked twice.
Because of these limitations, real systems rarely rely on a raw LLM alone. You'll see grounding techniques next, and we'll build up further techniques — tools, retrieval-augmented generation, and agents — in later modules.

4.5. Hallucinations & Grounding

Now that you know why hallucinations happen, let's look at how prompting can help reduce them.

LLM
↓

↓

≠

Figure 4.0-5: Fluency Is Not the Same as Accuracy

Basic Grounding Techniques

Technique 1 — Provide source context: "Answer using only the supplied document."

Technique 2 — Define missing-information behavior: "If the answer is not present, respond with NOT_FOUND."

Technique 3 — Request supporting evidence: "Provide the section or statement that supports your answer."

Prompt engineering can reduce hallucinations, but prompting alone cannot guarantee factual correctness.

4.6. Reasoning-Oriented Prompting / Chain-of-Thought

Some tasks require multiple reasoning steps. Asking a model to approach a problem carefully and systematically can improve performance on certain reasoning tasks.

Direct: "What is 48 × 27 − 14?"

Reasoning-oriented: "Solve this step by step, showing each calculation: 48 × 27 − 14."

Asking for the steps gives the model room to work through the problem piece by piece instead of jumping straight from question to final answer. It's often useful for arithmetic, multi-step logic, and tasks with several dependent sub-steps.

Reasoning-oriented prompting does not always improve results. Its usefulness depends on the task and the model — simple tasks may see no benefit. Test before assuming it's helping.
Modern reasoning-capable models may perform substantial reasoning internally. Prompt engineering does not require exposing private chain-of-thought to the user. Focus on requesting a correct, well-structured result and, where useful, a concise explanation.

Topic Quiz (10 Questions)

1. What does the temperature setting control during text generation?
  • How many tokens the API is allowed to charge for.
  • How much the probability distribution is reshaped before a token is sampled — lower values make output more deterministic, higher values more varied.
  • The physical GPU temperature during inference.
  • The number of few-shot examples included in the prompt.
2. What is the key difference between training and inference?
  • Training and inference are two names for the exact same process.
  • Training is when the model learns and updates its weights; inference is when it generates output using what it already learned.
  • Inference always requires more GPU compute than training.
  • Training happens every time a user sends a prompt.
3. How is an LLM trained, at a high level?
  • By repeatedly predicting the next token on massive text data, measuring the error, and adjusting weights to reduce it, over enormous numbers of examples.
  • By manually writing rules for every possible input the model might see.
  • By copying answers directly from a search engine index at request time.
  • Through a one-time calculation that happens instantly when the model is first turned on.
4. What does backpropagation do?
  • It rolls the model back to a previous checkpoint after an error.
  • It determines how much each parameter contributed to the loss, so the parameters can be adjusted to reduce it.
  • It reverses the order of tokens before feeding them to the model.
  • It compresses the model's weights to save VRAM.
5. What is a hallucination in the context of LLMs?
  • A hardware error caused by GPU overheating during inference.
  • The model generating unsupported, incorrect, or fabricated information while sounding plausible.
  • A visual bug in the chat interface that duplicates messages.
  • A guaranteed result of setting temperature above 0.
6. Which of the following is an example of a grounding technique?
  • Instructing the model to answer only using a supplied document, and to say NOT_FOUND if the answer isn't present.
  • Increasing the temperature to make responses more creative.
  • Removing all instructions so the model can respond freely.
  • Asking the same question in five different languages.
7. What is reasoning-oriented (Chain-of-Thought) prompting?
  • A guarantee that the model will always compute the mathematically correct answer.
  • Asking the model to work through a problem step by step, which can help on some multi-step reasoning tasks.
  • A setting that exposes the model's internal GPU computations to the user.
  • A technique that only applies to code-generation tasks.
8. Why is prompt iteration important?
  • Because the first version of a prompt always fails completely.
  • Because prompts rarely work perfectly on the first try, and inspecting output to identify and fix specific failures reliably improves results.
  • Because the LLM provider requires at least three attempts per request.
  • Because it permanently updates the model's weights with each iteration.
9. In an AI agent, what role do prompts play?
  • They act as a control layer — defining system behavior, task instructions, available tools, and how results should be formatted.
  • They are only used once, when the agent is first installed.
  • They replace the need for any tools or external actions.
  • They are irrelevant once the agent has access to tools.
10. What does the "loss" represent during training?
  • The number of tokens dropped due to a full context window.
  • A number that measures how wrong the model's prediction was compared to the actual target token.
  • The amount of GPU memory freed after each training step.
  • The number of parameters removed during quantization.

Assignment 2: Temperature Sensitivity Experiment

Assignment 3: Hallucination & Grounding

Task: Take a short document that intentionally does not contain the answer to a question. Compare Prompt A: "Answer the question." against Prompt B: "Answer only using the supplied document. If the answer is not present, respond with NOT_FOUND." Record and compare the two results.

Assignment 4: Prompt Iteration Challenge

Task: Starting from a deliberately poor prompt of your choice, improve it through at least three iterations. Document each version, the specific problem you observed in its output, and what you changed in response — Version 1 → problem observed → Version 2 → problem observed → Version 3 → final result.

Assignment 5: Agent Prompt Design

Task: Pick a simple agent scenario (e.g., a customer-support agent that can look up an order status). Sketch the prompt components it would need: the system instructions (role and rules), the tools it's allowed to use and when, the format its final response should take, and what it should do if a tool call fails. You don't need to write code — just design the prompt structure.
