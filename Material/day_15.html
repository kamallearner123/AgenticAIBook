1. The Paradigm Shift: From Fixed Pipeline to Agentic Routing

In Traditional RAG, retrieval is a fixed step in an unbending sequence: Query → Vector Search → Prompt → LLM. The pipeline has no mechanism to determine whether retrieval is actually necessary, cannot query multiple heterogeneous data silos (SQL vs Vector vs Live REST), and cannot execute follow-up computational actions based on what it reads.

In Agentic RAG, the Vector Database is treated as simply one specialized tool among many in the agent's toolbox. An orchestrating agent dynamically decides which tool to call, inspects retrieved excerpts, performs calculations, and self-reflects if retrieved evidence is insufficient:

USER QUERY: "What is our severance formula, and what is the payout for 4 years at ₹1,20,000/month?"
→ THOUGHT 1: "I need to look up company severance policy rules first."
→ ACTION 1: search_company_policies(query="severance formula")
← OBSERVATION 1: "Severance = 0.5 * monthly_salary * years_of_service"
→ THOUGHT 2: "Formula found. Now I compute arithmetic: 0.5 * 120000 * 4 via calculator tool."
→ ACTION 2: run_calculator(expression="0.5 * 120000 * 4")
← OBSERVATION 2: {"result": 240000.0}
→ FINAL SYNTHESIS: "Policy provides half-month salary per year. For 4 years at ₹1,20,000/mo, total payout is ₹2,40,000 INR."

2. Theory: Self-RAG Reflection & Adaptive Routing Mathematics

Self-RAG Reflection Tokens (Asai et al., 2023)

In standard RAG, the model blindly consumes whatever the retriever returns. Self-RAG introduces programmatic reflection evaluations at each phase:

  • 1. Retrieval Decision ($IsRetrieve$): Does the query require external knowledge? If conversational or pure math, $IsRetrieve = \text{False}$, eliminating vector search latency.
  • 2. Relevance Assessment ($IsRel$): Are the retrieved documents relevant to the query? $$\text{Score}_{\text{rel}} = P(\text{Relevant} \mid Q, D)$$ If $\text{Score}_{\text{rel}} < 0.60$, trigger a Query Rewrite step rather than generating hallucinated summaries.
  • 3. Grounding Verification ($IsSup$): Does the retrieved context fully support the generated response without ungrounded extrapolation?

Expected Query Latency & Cost Modeling

Let $P(\text{Direct})$ be the probability of a simple query, $P(\text{Calc})$ for computational queries, and $P(\text{RAG})$ for documentation lookups. Expected system latency is:

E[T] = P(\text{Direct}) T_{\text{LLM}} + P(\text{Calc}) (T_{\text{Tool}} + T_{\text{LLM}}) + P(\text{RAG}) (T_{\text{Embed}} + T_{\text{ANN}} + T_{\text{LLM}})

In an enterprise customer portal where 40% of queries are conversational greetings and 25% are account calculations, Agentic RAG slashes vector database load by 65% compared to traditional static RAG pipelines!

3. Program 1: Production Multi-Silo Agentic RAG (Vector + SQLite + Math)

The code below implements an enterprise Agentic RAG system that dynamically routes between an unstructured ChromaDB policy store, a structured SQLite customer database, and a local calculator tool:

program_15_1_multi_silo_agentic_rag.py 

# Program 15.0-1: Multi-Silo Agentic RAG (ChromaDB + SQLite + Python Calculator)
import json
import math
import sqlite3
from typing import Dict, Any, List
import chromadb
from openai import OpenAI

client = OpenAI()

# 1. UNSTRUCTURED VECTOR STORE (ChromaDB)
chroma_client = chromadb.Client()
policy_coll = chroma_client.get_or_create_collection("service_sla_policies")
policy_coll.add(
    documents=[
        "SLA Section 4B: If system availability drops below 99.9% in a calendar month, customer is entitled to a 10% invoice credit.",
        "SLA Section 4C: If an unscheduled downtime exceeds 4 continuous hours, an additional 5% penalty credit applies.",
        "Enterprise Plan: Base subscription rate is ₹4,50,000 INR per month for up to 5,000 active cloud instances."
    ],
    ids=["sla_4b", "sla_4c", "plan_enterprise"]
)

# 2. STRUCTURED RELATIONAL STORE (SQLite)
conn = sqlite3.connect(":memory:")
cursor = conn.cursor()
cursor.execute("""
    CREATE TABLE customer_outages (
        customer_id TEXT,
        company_name TEXT,
        downtime_hours REAL,
        monthly_bill_inr REAL
    )
""")
cursor.execute("INSERT INTO customer_outages VALUES ('CUST-8812', 'Tata Motors EV Division', 4.5, 450000.0)")
cursor.execute("INSERT INTO customer_outages VALUES ('CUST-9901', 'Bharat Electronics', 1.8, 220000.0)")
conn.commit()

# 3. TOOL FUNCTIONS
def search_sla_contracts(query: str) -> str:
    """Retrieve unstructured legal clauses from enterprise SLA and contract documents."""
    results = policy_coll.query(query_texts=[query], n_results=2)
    return "\n---\n".join(results["documents"][0])

def query_customer_incident_db(customer_id: str) -> str:
    """Query structured SQLite records for customer outage duration and billing stats."""
    cursor.execute("SELECT company_name, downtime_hours, monthly_bill_inr FROM customer_outages WHERE customer_id = ?", (customer_id,))
    row = cursor.fetchone()
    if row:
        return json.dumps({"company": row[0], "downtime_hours": row[1], "monthly_bill_inr": row[2]})
    return json.dumps({"error": f"Customer {customer_id} not found."})

def execute_math_calculation(expression: str) -> str:
    """Safely evaluates exact mathematical credit and penalty expressions."""
    try:
        allowed = {"abs": abs, "round": round}
        val = eval(expression, {"__builtins__": None}, allowed)
        return json.dumps({"status": "success", "result": round(float(val), 2)})
    except Exception as e:
        return json.dumps({"status": "error", "message": str(e)})

tools_schema = [
    {
        "type": "function",
        "function": {
            "name": "search_sla_contracts",
            "description": "Search contract terms, uptime requirements, and penalty percentages",
            "parameters": {
                "type": "object",
                "properties": {"query": {"type": "string"}},
                "required": ["query"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "query_customer_incident_db",
            "description": "Retrieve outage hours and monthly invoice bill for a customer ID",
            "parameters": {
                "type": "object",
                "properties": {"customer_id": {"type": "string"}},
                "required": ["customer_id"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "execute_math_calculation",
            "description": "Calculate exact monetary values and percentages",
            "parameters": {
                "type": "object",
                "properties": {"expression": {"type": "string"}},
                "required": ["expression"]
            }
        }
    }
]

# 4. ORCHESTRATOR LOOP
def run_agentic_rag(user_goal: str, max_turns: int = 6) -> str:
    messages = [
        {
            "role": "system",
            "content": (
                "You are an Autonomous Enterprise SLA Auditor. "
                "To resolve customer claims: 1) Query the SQL database for customer incident metrics, "
                "2) Search the SLA policy contract for applicable penalty clauses, "
                "3) Execute deterministic calculations using the calculator tool, "
                "and 4) Synthesize an audit resolution letter with full mathematical proof."
            )
        },
        {"role": "user", "content": user_goal}
    ]
    
    for turn in range(1, max_turns + 1):
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=tools_schema,
            temperature=0.0
        )
        msg = resp.choices[0].message
        messages.append(msg)
        
        if not msg.tool_calls:
            return msg.content
            
        for tc in msg.tool_calls:
            fn = tc.function.name
            args = json.loads(tc.function.arguments)
            print(f"  [Turn {turn}] Action: {fn}({args})")
            
            if fn == "search_sla_contracts":
                out = search_sla_contracts(args.get("query", ""))
            elif fn == "query_customer_incident_db":
                out = query_customer_incident_db(args.get("customer_id", ""))
            elif fn == "execute_math_calculation":
                out = execute_math_calculation(args.get("expression", ""))
            else:
                out = json.dumps({"error": "Unknown tool"})
                
            print(f"     Observation: {out[:90]}...")
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": out})
            
    return "Agent exceeded maximum turns without reaching conclusion."

if __name__ == "__main__":
    claim_query = "What total credit in INR is owed to customer CUST-8812 based on their outage last week under our SLA policy?"
    print(f"User Query: '{claim_query}'\n")
    final_resolution = run_agentic_rag(claim_query)
    print("\n" + "=" * 25 + " AUDIT RESOLUTION " + "=" * 25)
    print(final_resolution)

4. Program 2: Self-Reflective Retrieval with Automatic Query Rewriting

When initial vector search returns irrelevant documents, static RAG produces hallucinated summaries. The Self-RAG engine below programmatically grades retrieved document relevance; if relevance falls below threshold, it rewrites the query and re-retrieves:

program_15_2_self_rag_rewriter.py 

# Program 15.0-2: Self-Reflective Document Grader & Query Rewriter
from typing import List, Literal
from pydantic import BaseModel, Field
from openai import OpenAI

client = OpenAI()

class DocumentRelevanceGrade(BaseModel):
    is_relevant: bool = Field(description="True if the document contains facts directly answering the query")
    confidence: float = Field(ge=0.0, le=1.0)
    missing_aspects: List[str]

class QueryRewrite(BaseModel):
    optimized_query: str = Field(description="Re-formulated query removing conversational filler and adding key domain keywords")

def grade_retrieved_documents(query: str, retrieved_context: str) -> DocumentRelevanceGrade:
    """Grades whether the retrieved text actually contains the answer."""
    prompt = f"""
    You are an Adversarial Retrieval Grader.
    Assess whether the following retrieved context is factually sufficient to answer the user query.
    
    USER QUERY: {query}
    RETRIEVED CONTEXT:
    {retrieved_context}
    """
    comp = client.beta.chat.completions.parse(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        response_format=DocumentRelevanceGrade,
        temperature=0.0
    )
    return comp.choices[0].message.parsed

def rewrite_query_for_retrieval(query: str, missing_aspects: List[str]) -> str:
    """Rewrites the query targeting the missing semantic aspects."""
    prompt = f"""
    The following query failed to retrieve relevant documents: '{query}'
    Missing information: {missing_aspects}
    Rewrite this query into an optimized keyword search for an enterprise technical manual.
    """
    comp = client.beta.chat.completions.parse(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        response_format=QueryRewrite,
        temperature=0.2
    )
    return comp.choices[0].message.parsed.optimized_query

if __name__ == "__main__":
    original_query = "What happens if our EV coolant leaks?"
    flawed_retrieved_text = "The car infotainment screen supports wireless Apple CarPlay and Android Auto with 10 speaker audio."
    
    print(f"Evaluating Query: '{original_query}'")
    grade = grade_retrieved_documents(original_query, flawed_retrieved_text)
    print(f"Relevance Passed: {grade.is_relevant} (Confidence: {grade.confidence})")
    print(f"Missing Aspects: {grade.missing_aspects}")
    
    if not grade.is_relevant:
        better_query = rewrite_query_for_retrieval(original_query, grade.missing_aspects)
        print(f"\n--> Self-RAG Triggered Query Rewrite: '{better_query}'")

5. Program 3: Multi-Hop Document Reasoning Agent

Enterprise questions often require cross-referencing information scattered across multiple separate documents (e.g. Doc A states policy parameters, while Doc B states customer usage tiers). The multi-hop agent below executes sequential search passes, resolving intermediate facts until the complete cross-document deduction is assembled:

program_15_3_multihop_reasoner.py 

# Program 15.0-3: Multi-Hop Document Reasoning Agent
import json
from openai import OpenAI

client = OpenAI()

mock_knowledge_base = {
    "project chetak": "Project Chetak is the internal code name for the 2026 Commercial Electric Bus chassis.",
    "chetak battery supplier": "Project Chetak utilizes 120 kWh LFP battery modules supplied exclusively by Exide Energy.",
    "exide energy warranty": "Exide Energy provides an 8-year or 500,000 km warranty for commercial bus battery packs."
}

def search_internal_wiki(keyword: str) -> str:
    """Mock document search across company wiki pages."""
    k = keyword.lower().strip()
    for title, content in mock_knowledge_base.items():
        if k in title or title in k:
            return json.dumps({"status": "found", "title": title, "content": content})
    return json.dumps({"status": "not_found", "message": f"No wiki pages matching '{keyword}'."})

tools = [
    {
        "type": "function",
        "function": {
            "name": "search_internal_wiki",
            "description": "Search internal engineering and partnership wiki",
            "parameters": {
                "type": "object",
                "properties": {"keyword": {"type": "string"}},
                "required": ["keyword"]
            }
        }
    }
]

def run_multihop_agent(complex_question: str) -> str:
    messages = [
        {
            "role": "system",
            "content": (
                "You are an investigative engineering intelligence agent. "
                "To answer multi-hop questions, identify intermediate unknowns, search for each fact sequentially, "
                "and connect the chain of evidence before formulating your final answer."
            )
        },
        {"role": "user", "content": complex_question}
    ]
    
    for hop in range(1, 5):
        resp = client.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools, temperature=0.0)
        msg = resp.choices[0].message
        messages.append(msg)
        
        if not msg.tool_calls:
            return msg.content
            
        for tc in msg.tool_calls:
            args = json.loads(tc.function.arguments)
            print(f"  [Hop {hop}] Sub-query: search_internal_wiki('{args['keyword']}')")
            res = search_internal_wiki(args["keyword"])
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": res})
            
    return "Multi-hop budget exhausted."

if __name__ == "__main__":
    hop_question = "What is the warranty coverage on the battery pack used in Project Chetak?"
    print(f"Multi-Hop Query: '{hop_question}'\n")
    final_answer = run_multihop_agent(hop_question)
    print("\nFINAL MULTI-HOP DEDUCTION:\n", final_answer)

6. Production Failure Modes & Engineering Gotchas

  • 1. Retrieval Hallucination Trap: When an agent believes that the answer must exist in documentation, it may query the vector store 10 times with subtle variations, ignoring external tools. Mitigation: Bound the retriever tool invocation limit to a maximum of 2 calls per user turn.
  • 2. Mixed-Context Confusion: Passing raw SQL table results and vector document paragraphs together in the same scratchpad can confuse the model's arithmetic. Mitigation: Tag observations with explicit semantic source markers: [SOURCE: SQL_RECORD] vs [SOURCE: POLICY_EXCERPT].
  • 3. Query Rewrite Semantic Drift: When rewrites are performed blindly, the rewriter may replace domain terms with generic synonyms (e.g. replacing "AIS-156" with "battery safety test"), causing vector search to miss the exact standard document. Mitigation: Instruct the query rewriter to preserve all numbers, acronyms, and proper nouns.
  • 4. Infinite Multi-Hop Recursion: In multi-hop reasoning, circular document citations (Doc A references Doc B, which references Doc A) can cause infinite loop hops. Mitigation: Maintain a visited entity set in the context history.

7. Traditional RAG vs. Agentic RAG Comparison Matrix

Dimension Traditional RAG Agentic RAG
Retrieval Invocation Forced unconditionally on 100% of queries. Dynamic; invoked only when factual domain knowledge is required.
Mathematical Execution Hallucinates numbers or guesses arithmetic in text. Delegates extracted parameters to deterministic calculator tools.
Data Source Diversity Limited to a single vector database index. Multi-silo: fuses Vector Stores, SQL databases, and REST APIs.
Error Recovery Fails silently if initial retrieval is irrelevant. Self-RAG: evaluates relevance, rewrites query, and re-retrieves.
