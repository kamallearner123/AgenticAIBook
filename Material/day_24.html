24.1. Formal Foundations: Cyber-Physical Automotive Protocols & ISO 26262 ASIL Risk

Automotive diagnostics operate under strict international standards: SAE J1979 / ISO 15031 (OBD-II) and ISO 14229 (Unified Diagnostic Services - UDS). Real-time vehicle telematics stream across Controller Area Network (CAN) 2.0B / CAN-FD frames with 11-bit or 29-bit identifiers:

$$\text{CAN Frame: } [ \text{ID}_{\text{CAN}} \mid \text{DLC} \mid \text{Mode} \mid \text{PID} \mid \text{Data Byte A} \mid \text{Data Byte B} \mid \dots ]$$ $$\text{ISO 26262 Risk: } \mathcal{R}_{\text{ASIL}} = \text{Severity} (\mathcal{S}) \times \text{Exposure} (\mathcal{E}) \times \text{Controllability} (\mathcal{C})$$
  • PID Decoding Engine: Engine RPM is polled via Mode 01, PID 0x0C where $\text{RPM} = \frac{256A + B}{4}$. Coolant temperature is polled via Mode 01, PID 0x05 where $T = A - 40^\circ\text{C}$.
  • Automotive Safety Integrity Level (ASIL): If a Diagnostic Trouble Code touches steering, braking (ABS/ESC), high-voltage EV battery contactors, or airbags, the hazard classification elevates to ASIL-C or ASIL-D. The agent must enforce a mandatory, non-bypassable interrupt_before gate requiring cryptographic Master Diagnostic Technician sign-off.

    builder.add_node("obd2_scan", obd2_telemetry_node)
    builder.add_node("oem_rag", oem_rag_retrieval_node)
    builder.add_node("pricing", pricing_calculator_node)
    builder.add_node("synthesis", technical_synthesis_node)
    builder.add_node("approval_node", master_tech_approval_node)
    builder.add_node("finalize", finalize_work_order_node)
    
    builder.set_entry_point("parse_vin")
    builder.add_edge("parse_vin", "obd2_scan")
    builder.add_edge("obd2_scan", "oem_rag")
    builder.add_edge("oem_rag", "pricing")
    builder.add_edge("pricing", "synthesis")

        "approval_node": "approval_node",
        "finalize": "finalize"
    })
    
    builder.add_edge("approval_node", "finalize")
    builder.add_edge("finalize", END)
    
    conn = sqlite3.connect(db_path, check_same_thread=False)
    saver = SqliteSaver(conn)
    
    return builder.compile(checkpointer=saver, interrupt_before=["approval_node"]), conn

"""
Program 24.2: Synthetic SAE J1979 CAN Bus Telemetry Streamer
Encodes and decodes raw 11-bit OBD-II CAN broadcast frames for live testing.
"""

import time
import struct
from typing import Dict, Any, Generator

class CANBusSimulator:
    def __init__(self, vin: str):
        self.vin = vin

    def encode_rpm_frame(self, rpm: float) -> bytes:
        """Encode engine RPM into standard SAE J1979 Mode 01 PID 0x0C frame."""
        raw_val = int(rpm * 4)
        byte_a = (raw_val >> 8) & 0xFF
        byte_b = raw_val & 0xFF
        # CAN Frame: [Length=4, Mode=0x01, PID=0x0C, ByteA, ByteB, 0xAA, 0xAA, 0xAA]
        return struct.pack("8B", 0x04, 0x01, 0x0C, byte_a, byte_b, 0xAA, 0xAA, 0xAA)

    def decode_rpm_frame(self, frame: bytes) -> float:
        """Decode raw CAN bytes back to physical RPM value."""
        length, mode, pid, byte_a, byte_b, _, _, _ = struct.unpack("8B", frame)
        assert mode == 0x01 and pid == 0x0C, "Invalid RPM PID frame!"
        return round(((byte_a * 256) + byte_b) / 4.0, 1)

    def telemetry_stream(self, samples: int = 5) -> Generator[Dict[str, Any], None, None]:
        print(f"Initializing CAN Bus Broadcast for VIN: {self.vin} (500 kbps High-Speed CAN)...")
        base_rpm = 2200.0
        
        for i in range(samples):
            current_rpm = base_rpm + (i * 125.0)
            raw_frame = self.encode_rpm_frame(current_rpm)
            decoded_rpm = self.decode_rpm_frame(raw_frame)
            
            yield {
                "can_id": "0x7E8", # Standard ECU broadcast address
                "raw_hex": raw_frame.hex(),
                "mode": "0x01",
                "pid": "0x0C",
                "physical_rpm": decoded_rpm,
                "timestamp_ms": int(time.time() * 1000)
            }
            time.sleep(0.05)

if __name__ == "__main__":
    sim = CANBusSimulator("1HGCR2F83HA001009")
    print("=== STREAMING RAW CAN BUS FRAMES ===")
    for packet in sim.telemetry_stream(samples=5):
        print(f"CAN Frame: {packet['can_id']} | Raw: {packet['raw_hex']} -> Decoded RPM: {packet['physical_rpm']}")
    print("✓ CAN Bus interrogation validated successfully.")

24.6. Production Failure Modes & Automotive Gotchas

Automotive Gotcha 1: Premature DTC Clearing Destroys Emissions Readiness

The Incident: A technician instructs an automated agent to "clear all error codes" to test if a fault re-occurs. Clearing DTCs in Mode 04 resets all OBD-II readiness monitors (Catalyst, Evap, O2 Sensor Heaters) to "Incomplete", causing the vehicle to fail state inspection until driven for 100+ miles.

Mitigation: Enforce strict tool permissions: the diagnostic agent must be restricted to read-only Mode 01 and Mode 03 commands. DTC clearing (Mode 04) is locked behind two-factor physical confirmation.

Automotive Gotcha 2: Intermittent CAN Bus Bus-Off State

The Incident: A faulty alternator introduces AC ripple voltage onto the 12V bus, causing intermittent frame CRC errors on the CAN transceiver. The agent flags 12 different ECUs as failed simultaneously.

Automotive Gotcha 3: Hallucinated Torque Specifications

The Incident: An LLM generates workshop advice recommending tightening brake caliper bracket bolts to "45 ft-lbs" when OEM specification requires 125 ft-lbs with threadlocker. Caliper bolts back out on the highway, causing brake failure.

Mitigation: Mechanical fasteners, fluid capacities, and torque specifications must never be synthesized from model memory; they must be retrieved strictly from OEM service manuals via RAG and verified against a deterministic lookup table.
