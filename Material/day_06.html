6.1. The Fundamental Limit of Text Prediction

As established in previous sessions, an LLM is a closed neural network. It possesses neither hands, network sockets, nor a Python runtime. When asked to perform complex floating-point arithmetic, it does not execute arithmetic logic; it emits the tokens that look like the answer based on statistical patterns—often failing on 5+ digit multiplications.

The solution is not to train larger models, but to equip the model with Tools. In an agentic architecture, the LLM acts as the Reasoning Engine (Brain), while deterministic external code (APIs, databases, Python scripts, CLI commands) acts as the Hands.

Real World Example: Voice assistants like Siri or Alexa. When you say: "Set my living room thermostat to 22 degrees," the voice model does not physically heat your home. It translates your spoken sentence into an API payload: {"device": "thermostat_living_room", "temperature": 22} and dispatches it over Wi-Fi. That is the exact mechanism behind LLM Tool Execution.

6.2. The Function Calling Lifecycle

Function Calling is a bi-directional handshake between your host Python application and the remote LLM inference server. The model never runs your code directly; it emits a structured JSON request instructing your application which function to run and with what arguments.

1. USER QUERY: "What is the stock price of TCS and calculate 18% GST on it?"
↓ [Model analyzes available tools: 'get_stock_price', 'calculator']
2. TOOL CALL EMITTED: get_stock_price(ticker="TCS.NS")
↓ [Host Python app fetches Yahoo Finance API → ₹4,200]
3. TOOL RESULT INJECTED: {"price": 4200.0, "currency": "INR"}
↓ [Model emits second tool call: calculator(expression="4200 * 0.18")]
4. FINAL SYNTHESIS: "TCS is ₹4,200. 18% GST is ₹756, total is ₹4,956."
Figure 6.0-1: The Multi-Step Tool Invocation Handshake Loop
Figure Parameters Explained:
  • Tool Declarations: The client sends JSON Schemas describing available functions, argument types, and descriptions to the model.
  • Tool Call Payload: When the model decides to invoke a tool, it halts regular text generation and outputs a tool_calls object containing a unique id, function name, and serialized arguments.
  • Tool Execution: Your Python app extracts the arguments, invokes the local function safely, and captures the result.
  • Tool Message: The result is injected back into the message history with role: "tool" and the matching tool_call_id.

# Program 6.0-1: Full End-to-End Tool Execution Engine
import json
import math
from openai import OpenAI

client = OpenAI()

# 1. Define local Python functions (The "Hands")
def calculate(expression: str) -> str:
    """Evaluates mathematical expressions safely."""
    try:
        # Restricted safe mathematical evaluation
        allowed_names = {"sqrt": math.sqrt, "pow": math.pow, "abs": abs}
        result = eval(expression, {"__builtins__": None}, allowed_names)
        return json.dumps({"result": float(result)})
    except Exception as e:
        return json.dumps({"error": f"Evaluation failed: {str(e)}"})

def get_current_weather(city: str) -> str:
    """Mock weather service returning live telemetry."""
    weather_db = {
        "mumbai": {"temp_c": 31, "condition": "Humid & Sunny", "humidity": 78},
        "bangalore": {"temp_c": 24, "condition": "Pleasant Breeze", "humidity": 55},
        "delhi": {"temp_c": 38, "condition": "Hot & Dry", "humidity": 25}
    }
    data = weather_db.get(city.lower(), {"temp_c": 25, "condition": "Unknown", "humidity": 50})
    return json.dumps(data)

# 2. Define JSON Schemas for the LLM
tools = [
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "Perform accurate mathematical and financial calculations",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "Math expression, e.g., '4200 * 0.18'"}
                },
                "required": ["expression"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "get_current_weather",
            "description": "Retrieve current temperature and weather conditions for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "City name, e.g., 'Bangalore'"}
                },
                "required": ["city"]
            }
        }
    }
]

# 3. Agentic Execution Loop
messages = [{"role": "user", "content": "What is the weather in Bangalore, and if I buy 3 umbrellas at 450 INR each plus 12% tax, what is my total cost?"}]

print("User Prompt:", messages[0]["content"])

# First turn: LLM decides to call tools
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=tools
)

response_message = response.choices[0].message
messages.append(response_message)

# Check if the model requested tool calls
if response_message.tool_calls:
    print(f"\nModel requested {len(response_message.tool_calls)} tool call(s):")
    
    for tool_call in response_message.tool_calls:
        fn_name = tool_call.function.name
        fn_args = json.loads(tool_call.function.arguments)
        print(f"  Executing: {fn_name}({fn_args})")
        
        # Route and execute
        if fn_name == "calculate":
            tool_output = calculate(fn_args["expression"])
        elif fn_name == "get_current_weather":
            tool_output = get_current_weather(fn_args["city"])
        else:
            tool_output = json.dumps({"error": "Unknown tool"})
            
        # Append result to message history
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": tool_output
        })

    # Second turn: LLM consumes tool outputs and generates final answer
    final_response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages
    )
    print("\nFinal Agent Response:")
    print(final_response.choices[0].message.content)

6.4. Tool Error Handling & Self-Healing Retries

In production, external APIs fail: database connections time out, rate limits are hit, or the LLM passes an invalid parameter. If your Python code throws an uncaught exception, your agent crashes.

Instead, catch the exception and serialize the error message back to the LLM as a tool result! High-capability models can inspect the error message, realize what argument was malformed, and emit a corrected tool call autonomously.

self_healing_tool_execution_on_failure.py 

# Program 6.0-2: Self-Healing Tool Execution on Failure
def safe_tool_executor(func, **kwargs) -> str:
    """Executes a tool and catches all exceptions, returning actionable error JSON."""
    try:
        output = func(**kwargs)
        return json.dumps({"status": "success", "data": output})
    except KeyError as ke:
        return json.dumps({"status": "error", "message": f"Missing required parameter: {ke}. Please retry with valid keys."})
    except Exception as err:
        return json.dumps({"status": "error", "message": f"Execution failed: {str(err)}. Attempt alternative method."})

# If an API times out, the model reads the error string and attempts a fallback tool!
print(safe_tool_executor(lambda: 1/0))

6.5. The Function Calling Wire Protocol & Token Overhead Mathematics

When you provide tools to an API, the provider serializes each tool definition into hidden system prompt tokens formatted in a specialized schema (such as TypeScript interface syntax or JSON Schema). Consider the economic and context window implications:

Tool Schema Context Sizing Rule of Thumb:
  • Each tool definition consumes between 150 and 350 tokens depending on parameter count and description verbosity.
  • A naive agent equipped with 25 tools incurs an automatic overhead of 5,000 to 8,000 input tokens on EVERY single turn, regardless of whether a tool is called!
  • At 100,000 queries per month, that tool schema overhead alone costs hundreds of dollars and adds 400ms of prefill latency per request.
Engineering Takeaway: Do not register all tools globally. Use dynamic tool registries or hierarchical router agents that only load the 3 or 4 tools relevant to the current classified intent!

Program 6.0-3: Automated `@tool` Decorator with Schema Introspection

Writing JSON schemas manually in raw dictionaries is error-prone. This production utility inspects any Python function's type annotations and docstring, compiling it automatically into an OpenAI-compatible function definition.

tool_decorator_registry.py 
# Program 6.0-3: Automated @tool Decorator and Registry
import inspect
from typing import Callable, Dict, Any, List

class ToolRegistry:
    """Central registry maintaining executable functions and their generated schemas."""
    def __init__(self):
        self._tools: Dict[str, Callable] = {}
        self._schemas: List[Dict[str, Any]] = []

    def register(self, func: Callable) -> Callable:
        """Decorator that compiles a Python function into an OpenAI tool schema."""
        sig = inspect.signature(func)
        doc = inspect.getdoc(func) or "No description provided."
        
        type_mapping = {
            str: "string",
            int: "integer",
            float: "number",
            bool: "boolean",
            list: "array",
            dict: "object"
        }
        
        properties = {}
        required = []
        
        for param_name, param in sig.parameters.items():
            param_type = type_mapping.get(param.annotation, "string")
            properties[param_name] = {
                "type": param_type,
                "description": f"Parameter {param_name}"
            }
            if param.default == inspect.Parameter.empty:
                required.append(param_name)
                
        schema = {
            "type": "function",
            "function": {
                "name": func.__name__,
                "description": doc,
                "parameters": {
                    "type": "object",
                    "properties": properties,
                    "required": required
                }
            }
        }
        
        self._tools[func.__name__] = func
        self._schemas.append(schema)
        return func

    def get_schemas(self) -> List[Dict[str, Any]]:
        return self._schemas

    def execute(self, tool_name: str, **kwargs) -> Any:
        if tool_name not in self._tools:
            raise ValueError(f"Tool '{tool_name}' is not registered.")
        return self._tools[tool_name](**kwargs)

# Example: Declaring Clean Agent Tools
registry = ToolRegistry()

@registry.register
def query_stock_price(ticker: str, include_extended_hours: bool = False) -> str:
    """Fetch the real-time stock valuation for a given publicly traded equity ticker."""
    return f"Ticker {ticker.upper()}: $182.40 (Extended: {include_extended_hours})"

@registry.register
def calculate_compound_interest(principal: float, annual_rate: float, years: int) -> float:
    """Calculates future investment value with annual compounding."""
    return round(principal * ((1 + annual_rate) ** years), 2)

print("=== AUTOMATICALLY GENERATED TOOL SCHEMAS ===")
import json
print(json.dumps(registry.get_schemas(), indent=2))

print("\n=== EXECUTING REGISTERED TOOL VIA DISPATCHER ===")
res = registry.execute("calculate_compound_interest", principal=10000.0, annual_rate=0.07, years=5)
print(f"Calculation Result: ${res}")

Program 6.0-4: Sandboxed Code Execution Tool

Agents that execute generated Python code must never use raw eval() or exec() on the host process. This program demonstrates executing Python in an isolated subprocess with timeout and memory constraints.

sandboxed_code_executor.py 
# Program 6.0-4: Subprocess-Sandboxed Python Execution Tool
import subprocess
import sys
import tempfile
import os

def run_sandboxed_python(code_snippet: str, timeout_seconds: int = 3) -> dict:
    """
    Executes generated Python code inside an isolated subprocess with timeouts.
    Blocks direct host memory compromise and halts infinite loops.
    """
    # Prohibit dangerous OS calls
    forbidden = ["os.system", "shutil.rmtree", "subprocess", "eval", "__import__('os')"]
    if any(f in code_snippet for f in forbidden):
        return {"status": "REJECTED", "error": "Security Policy Violation: Prohibited syscall detected."}
        
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=False) as tmp_file:
        tmp_file.write(code_snippet)
        tmp_path = tmp_file.name

    try:
        proc = subprocess.run(
            [sys.executable, tmp_path],
            capture_output=True,
            text=True,
            timeout=timeout_seconds
        )
        return {
            "status": "SUCCESS" if proc.returncode == 0 else "RUNTIME_ERROR",
            "stdout": proc.stdout.strip(),
            "stderr": proc.stderr.strip(),
            "returncode": proc.returncode
        }
    except subprocess.TimeoutExpired:
        return {"status": "TIMEOUT", "error": f"Execution timed out after {timeout_seconds} seconds (Infinite loop prevented)."}
    finally:
        if os.path.exists(tmp_path):
            os.remove(tmp_path)

# Test 1: Legitimate computation
clean_code = "print([x**2 for x in range(1, 6)])"
print("=== TEST 1: SAFE CODE EXECUTION ===")
print(run_sandboxed_python(clean_code))

# Test 2: Malicious script attempting host compromise
malicious_code = "import os; os.system('rm -rf /')"
print("\n=== TEST 2: BLOCKED MALICIOUS SYSCALL ===")
print(run_sandboxed_python(malicious_code))

# Test 3: Infinite loop attempt
infinite_loop = "while True: pass"
print("\n=== TEST 3: INFINITE LOOP CIRCUIT BREAKER ===")
print(run_sandboxed_python(infinite_loop, timeout_seconds=1))

6.7. Tool Execution Security Best Practices

  1. Never Expose Unparameterized SQL or Shell Tools: A generic run_bash(cmd) tool converts any prompt injection into a remote code execution (RCE) server breach. Use granular, single-purpose functions instead (e.g. fetch_user_by_id(id)).
  2. Validate Read vs. Write Scopes: Tools that mutate data (e.g., delete_account, send_wire_transfer) must enforce human confirmation gates before execution.
  3. Sanitize Error Messages Returned to the Model: Avoid sending raw database stack traces containing database passwords or server paths back into the LLM context.
  4. Enforce Strict Request Timeouts: All external HTTP or database tools must have 2–5 second socket timeouts to prevent agents from hanging indefinitely.
