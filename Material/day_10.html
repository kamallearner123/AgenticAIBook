10.1. The Mechanics of Dynamic Tool Selection

When you provide an array of tools to a foundation model, the model does not execute code or inspect your Python function bodies. It performs in-context semantic matching between the user's intent and the description, parameters, and docstrings defined in the OpenAPI schema.

Thought: "The user needs to retrieve customer CUST-101's account and calculate a 15% discount if spend > ₹500,000."
Action 1: query_customer_database(customer_id="CUST-101")
Observation 1: {"name": "Infosys Tech", "total_spend_inr": 850000, "status": "Platinum"}
Thought: "Spend is ₹850,000 (> ₹500,000). Now I calculate 15% discount: 850000 * 0.15."
Action 2: run_calculator(expression="850000 * 0.15")
Observation 2: {"status": "success", "result": 127500.0}
Final Answer: "Customer Infosys Tech has total spend of ₹850,000. Their 15% renewal discount is ₹127,500."

10.2. Theory: Two-Stage Semantic Tool Retrieval for Large Catalogs

The Tool Bloat Problem & Mathematical Sizing

Each tool schema in the OpenAI function specification consumes approximately $150 \text{ to } 350 \text{ tokens}$. If an enterprise platform provides $M = 50$ enterprise tools:

$$\text{Baseline Overhead per Turn} = 50 \times 250 \approx 12,500 \text{ tokens}$$

Across a 6-turn agent trajectory, this overhead wastes 75,000 tokens solely defining irrelevant tools! Even worse, large tool catalogs trigger Tool Confusion, where models pick the wrong tool because of overlapping keywords.

The Vector-Indexed Two-Stage Solution

Instead of passing all $M$ tools to the LLM, we embed tool descriptions into a dense vector index. On each turn, given user query $q$, we compute cosine similarity between the query embedding $e_q$ and all tool description embeddings $e_{t_i}$:

$$\text{Sim}(q, t_i) = \frac{e_q \cdot e_{t_i}}{\|e_q\|_2 \|e_{t_i}\|_2}$$

We dynamically select the Top-$k$ (e.g., $k=4$) highest scoring tools, slashing token consumption by 92% and eliminating model distraction.

10.3. Program 1: Dynamic Multi-Tool Registry with Pydantic v2 Introspection

The code below demonstrates a production tool registry with an automated @agent_tool decorator that uses type introspection to compile OpenAPI JSON schemas directly from Python signatures:

program_10_1_dynamic_tool_registry.py 

# Program 10.0-1: Production Multi-Tool Registry with Pydantic Introspection
import inspect
import json
import math
from typing import Callable, Dict, Any, List, Optional
from pydantic import BaseModel, Field, create_model
from openai import OpenAI

client = OpenAI()

class ToolRegistry:
    def __init__(self):
        self.tools: Dict[str, Callable] = {}
        self.schemas: List[Dict[str, Any]] = []

    def register(self, name: Optional[str] = None, description: Optional[str] = None):
        """Decorator to register a typed Python function into the agent's tool catalog."""
        def decorator(func: Callable):
            fn_name = name or func.__name__
            fn_doc = description or (func.__doc__ or "No description provided.").strip()
            
            sig = inspect.signature(func)
            fields: Dict[str, Any] = {}
            
            for param_name, param in sig.parameters.items():
                param_type = param.annotation if param.annotation != inspect.Parameter.empty else str
                default_val = param.default if param.default != inspect.Parameter.empty else ...
                fields[param_name] = (param_type, default_val)
                
            ParamModel = create_model(f"{fn_name}_args", **fields)
            
            tool_spec = {
                "type": "function",
                "function": {
                    "name": fn_name,
                    "description": fn_doc,
                    "parameters": ParamModel.model_json_schema()
                }
            }
            
            self.tools[fn_name] = func
            self.schemas.append(tool_spec)
            return func
        return decorator

    def dispatch(self, tool_name: str, arguments_json: str) -> str:
        """Safely parses arguments and executes the registered tool."""
        if tool_name not in self.tools:
            return json.dumps({"status": "error", "message": f"Tool '{tool_name}' is not registered."})
        
        try:
            args = json.loads(arguments_json)
            func = self.tools[tool_name]
            result = func(**args)
            return json.dumps({"status": "success", "result": result})
        except Exception as err:
            return json.dumps({"status": "error", "message": f"Execution failed: {str(err)}"})

# Initialize registry
registry = ToolRegistry()

@registry.register(description="Perform high-precision mathematical and algebraic calculations")
def calculate_expression(expression: str) -> float:
    sanitized = expression.replace("^", "**")
    allowed = {"sqrt": math.sqrt, "abs": abs, "pow": math.pow}
    return float(eval(sanitized, {"__builtins__": None}, allowed))

@registry.register(description="Retrieve customer profile, billing status, and total revenue in INR")
def lookup_customer(customer_id: str) -> Dict[str, Any]:
    mock_db = {
        "CUST-101": {"name": "Infosys Tech", "total_spend_inr": 850000, "status": "Platinum"},
        "CUST-102": {"name": "Wipro Global", "total_spend_inr": 420000, "status": "Gold"}
    }
    return mock_db.get(customer_id, {"error": "Customer not found"})

@registry.register(description="Retrieve live meteorological conditions for an Indian tech hub")
def get_weather(city: str) -> Dict[str, Any]:
    return {"city": city, "temperature_c": 28.5, "condition": "Overcast", "humidity_percent": 65}

def run_multi_tool_agent(prompt: str) -> str:
    messages = [
        {"role": "system", "content": "You are an autonomous operations assistant. Use tools to verify all data."},
        {"role": "user", "content": prompt}
    ]
    
    for step in range(1, 5):
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=registry.schemas,
            temperature=0.0
        )
        msg = resp.choices[0].message
        messages.append(msg)
        
        if not msg.tool_calls:
            return msg.content
            
        for tc in msg.tool_calls:
            print(f"[Turn {step}] Model selecting: {tc.function.name} with args: {tc.function.arguments}")
            tool_output = registry.dispatch(tc.function.name, tc.function.arguments)
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": tool_output})
            
    return "Max steps exhausted."

if __name__ == "__main__":
    task = "Find customer CUST-101. If their spend > 500,000 INR, calculate a 12% loyalty rebate and check weather in Bengaluru."
    print("Agent Result:\n", run_multi_tool_agent(task))

10.4. Program 2: Two-Stage Semantic Tool Retrieval Engine

When an enterprise provides 30+ tools, passing all definitions causes massive context bloat. The implementation below uses dense vector embeddings to index tool capabilities, retrieving only the Top-3 relevant tools per turn:

program_10_2_semantic_tool_search.py 

# Program 10.0-2: Two-Stage Semantic Tool Retrieval with Vector Embeddings
import numpy as np
from typing import List, Dict, Any
from openai import OpenAI

client = OpenAI()

class SemanticToolIndex:
    def __init__(self, catalog: List[Dict[str, Any]]):
        self.catalog = catalog
        self.embeddings: List[np.ndarray] = []
        self._build_index()

    def _get_embedding(self, text: str) -> np.ndarray:
        resp = client.embeddings.create(model="text-embedding-3-small", input=text)
        return np.array(resp.data[0].embedding, dtype=np.float32)

    def _build_index(self):
        print(f"Embedding {len(self.catalog)} enterprise tool descriptions...")
        for tool in self.catalog:
            desc = f"{tool['function']['name']}: {tool['function']['description']}"
            self.embeddings.append(self._get_embedding(desc))

    def retrieve_top_k(self, query: str, k: int = 3) -> List[Dict[str, Any]]:
        """Computes cosine similarity and returns top-k tools."""
        q_emb = self._get_embedding(query)
        q_norm = np.linalg.norm(q_emb)
        
        scores = []
        for idx, t_emb in enumerate(self.embeddings):
            sim = np.dot(q_emb, t_emb) / (q_norm * np.linalg.norm(t_emb))
            scores.append((sim, idx))
            
        scores.sort(key=lambda x: x[0], reverse=True)
        top_tools = [self.catalog[idx] for _, idx in scores[:k]]
        return top_tools

# Expanded enterprise catalog (simulated 8 diverse tools)
enterprise_catalog = [
    {"type": "function", "function": {"name": "query_sql", "description": "Execute read-only SQL queries against Postgres database"}},
    {"type": "function", "function": {"name": "calculate_roi", "description": "Calculate return on investment, net present value, and IRR"}},
    {"type": "function", "function": {"name": "fetch_jira_ticket", "description": "Retrieve agile ticket status, assignee, and comments"}},
    {"type": "function", "function": {"name": "query_ec2_instances", "description": "List active AWS cloud compute instances and CPU metrics"}},
    {"type": "function", "function": {"name": "send_slack_alert", "description": "Post notifications to engineering incident Slack channels"}},
    {"type": "function", "function": {"name": "search_patents", "description": "Search USPTO and European patent office legal filings"}},
    {"type": "function", "function": {"name": "ping_dns_server", "description": "Test network latency and packet loss to hostname"}},
    {"type": "function", "function": {"name": "scan_docker_vulnerabilities", "description": "Scan container images for CVE security flaws"}}
]

if __name__ == "__main__":
    indexer = SemanticToolIndex(enterprise_catalog)
    
    test_query = "Our production server is running slow and we need to check CPU utilization on our cloud servers."
    selected_tools = indexer.retrieve_top_k(test_query, k=2)
    
    print("\n" + "=" * 25 + " TOP-2 RETRIEVED TOOLS " + "=" * 25)
    for t in selected_tools:
        print(f" -> {t['function']['name']}: {t['function']['description']}")

10.5. Program 3: Resilient Tool Dispatcher with Auto-Coercion & Error Healing

LLMs sometimes pass integer strings ("850000") when a tool expects a float (850000.0), or miss mandatory parameters. The resilient dispatcher below intercepts validation errors, auto-coerces types, and feeds structured error feedback back to the LLM if coercion fails:

program_10_3_resilient_dispatcher.py 

# Program 10.0-3: Resilient Tool Dispatcher with Type Auto-Coercion
import json
from typing import Dict, Any, Callable
from pydantic import BaseModel, Field, ValidationError

class TaxCalculationParams(BaseModel):
    annual_income_inr: float = Field(..., ge=0.0, description="Gross taxable income in INR")
    tax_slab_percentage: float = Field(..., ge=0.0, le=50.0, description="Percentage rate e.g., 20.0")

def compute_tax(annual_income_inr: float, tax_slab_percentage: float) -> Dict[str, Any]:
    tax_due = annual_income_inr * (tax_slab_percentage / 100.0)
    return {"status": "success", "tax_payable_inr": tax_due, "net_takehome": annual_income_inr - tax_due}

def safe_dispatch_with_coercion(raw_json_args: str) -> str:
    """Validates raw LLM arguments against Pydantic schema with auto-coercion."""
    try:
        parsed_dict = json.loads(raw_json_args)
    except json.JSONDecodeError as e:
        return json.dumps({"status": "error", "error_type": "JSONDecodeError", "message": f"Malformed JSON: {str(e)}"})

    try:
        validated = TaxCalculationParams(**parsed_dict)
        result = compute_tax(validated.annual_income_inr, validated.tax_slab_percentage)
        return json.dumps(result)
    except ValidationError as val_err:
        errors = [f"Field '{e['loc'][0]}': {e['msg']}" for e in val_err.errors()]
        return json.dumps({
            "status": "validation_failed",
            "error_type": "ValidationError",
            "errors": errors,
            "instruction": "Please correct the argument types and retry."
        })

if __name__ == "__main__":
    # Test 1: String coercion (Pydantic auto-converts string numbers to floats)
    test_1 = '{"annual_income_inr": "1800000", "tax_slab_percentage": "30"}'
    print("Test 1 (Auto-Coercion):", safe_dispatch_with_coercion(test_1))

    # Test 2: Invalid percentage (> 50%)
    test_2 = '{"annual_income_inr": 1800000, "tax_slab_percentage": 75.0}'
    print("Test 2 (Validation Guard):", safe_dispatch_with_coercion(test_2))

10.6. Production Failure Modes & Engineering Gotchas

  • 1. Tool Name Collisions: Having tools with overlapping names (e.g., search_database vs query_database) confuses the model's logits, leading to random tool switching across turns. Mitigation: Namespace tools by resource domain (e.g., postgres_query vs confluence_search).
  • 2. Unbounded Observation Bloat: If a tool like query_sql returns a 10,000-row table, dumping the entire JSON array into the observation crashes the context window. Mitigation: Paginate tool outputs; return a maximum of 10 rows with an explicit "total_rows_truncated": 9990 notice.
  • 3. Silent Type Failure: Passing string floats into strict functions causing Python TypeError crashes. Mitigation: Always wrap tool parameter payloads in Pydantic models with auto-coercion enabled.
  • 4. Lack of Negative Constraints in Docstrings: LLMs love calling tools. If you have a tool called send_email, the model will call it even when asked to "draft" an email. Mitigation: Explicitly state negative conditions: "Do NOT call this tool if the user only wants to preview or review an email draft."
